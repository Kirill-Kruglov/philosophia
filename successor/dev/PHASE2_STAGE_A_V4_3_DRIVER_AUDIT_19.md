## Reproduced pre-confirmation defects

1. **Learner identity still depends on ambient default dtype.** With the same
   validated spec (`dtype=float32`, `init_seed=0`) and the same pinned software,
   construction under ambient `torch.float32` produced state hash
   `0fa58f6727b770644db32d456f39bbc94ebea232db350b4b09a0996830da7e94`,
   while ambient `torch.float64` produced
   `83f96c8149d387723e72486d26b6739a96c52109d9efc9fbd98521465863aa90`.
   Moving the already initialized model to the declared dtype does not repair
   different initialization draws. Model construction must scope and restore
   ambient default dtype as well as RNG, and must force initial allocation on
   CPU before the declared device move.

2. **The accepted seed domain is non-canonical on the pinned Torch CPU
   generator.** Seeds `0` and `2**63`, `1` and `2**63+1`, and `2**63-1` and
   `2**64-1` generated byte-identical random streams. The current
   `[0, 2**64-1]` domain therefore gives two spec identities to the same RNG
   identity. Narrow it to exact integers in `[0, 2**63-1]` and test the rejected
   first aliasing seed `2**63`.

3. **A malformed dtype escapes the typed pre-spawn refusal.** Setting
   `dtype=[]` makes `validate_scientific_spec` raise raw
   `TypeError: unhashable type: 'list'`; the public parser catches only
   `ScientificSpecError`. Require `type(dtype) is str` before membership and
   prove the public call returns `IsolatedInvalidSpec` without requesting a
   multiprocessing context.

4. **The PEANO_PANIC envelope validates shape but not semantic identity.** An
   envelope carrying `exception_module='fake.module'` and
   `exception_class='FakePanic'` is reconstructed as `PeanoPanicRefusal`.
   Require the exact concrete identity already used by `is_pyo3_panic`:
   `pyo3_runtime.PanicException`; any other values are a malformed envelope and
   must become `IsolatedJobError`.

These are local boundary corrections, not a reopened scientific design. Stage B
remains unauthorized.
