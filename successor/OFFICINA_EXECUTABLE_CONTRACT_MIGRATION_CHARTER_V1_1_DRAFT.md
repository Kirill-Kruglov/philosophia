# Officina executable-contract migration charter v1.1 (draft)

**Status:** draft. Not accepted. Authorizes nothing until the §10 tokens are signed after
byte-identical independent X/Y confirmation of these bytes.

**Purpose.** Replace prose-as-executable-authority with a small machine-checkable contract,
preserving every signed scientific and author choice, and removing the generation/provenance drift
that consumed more than one hundred review/repair iterations.

**Scope boundary.** A route decision. It creates no code, contract, fixture, schema, manifest,
test, Git object or archive operation. It accepts, repairs and supersedes no candidate. It moves
no `OR` step and no claim.

```text
T = NOT_ACTIVATED
PROGRAMME CLAIM = OPEN
ATOMIC HANDOFF = OR-2 COMPLETE; OR-3..OR-11 NOT AUTHORIZED
```

**Revision basis.** v1.1 is the sole bounded revision of v1, applying the X line's mandatory E1–E9
and the Y line's mandatory edits 1–6; where the two differ, the stricter rule is taken. The v1
skeleton is preserved only where not superseded. The v1 §1 failure diagnosis (Classes A–D) is
retained by reference, not restated, and is normative for nothing here. There is no v1.2 in this
episode: if these bytes fail structurally, §8.3's redesign rule fires.

## §1. Authority graph, release binding, dependency policy

### §1.1 The graph

Acyclic. Edges point from authority to derived; nothing points back.

```text
  [signed choices] successor/*_SIGNATURE.md — unchanged Class-C authority
      │  read once at M1 into the equivalence ledger; never at runtime
      ▼
  AUTHORITATIVE SOURCE — hand-edited, reviewed: successor/officina/contract/
    constants.py  enums, cited protocol constants, route and token strings,
                  negative boundaries, the NORMATIVE_TEXT mapping
    schemas.py    frozen dataclasses, closed key sets, executable validators
    machines.py   fact-free evaluators (KG-2, PCS freeze classifier phases)
    data/*.json   dimensions, transition table, fixtures, vectors, atom register
      │                        │                        │
      ▼                        ▼                        ▼
  GENERATOR                TESTS + O1 ORACLE       PROVENANCE GATE
  tools/officina_contract/ tests/test_officina_     tools/officina_contract/
    render.py                contract_*.py            provenance.py
      │                                                 │  raw bytes only;
      ▼                                                 │  imports no renderer
  GENERATED — never hand-edited: successor/officina/generated/
    CONTRACT.md    documentation + derived tripwires    │
    MANIFEST.json  the ONE live manifest, contract/** ◄─┘
  VERIFIER  tools/officina_contract/verify.py --check [--release-ref <tag>]
```

### §1.2 Structural rules

1. **One authoritative representation per operative fact.** A fact lives in exactly one of
   `constants.py`, `schemas.py`, `machines.py` or `data/`, and appears in `CONTRACT.md` only as
   generator output.
2. **Markdown carries no independent authority.** If `CONTRACT.md` disagrees with `contract/`,
   `contract/` governs and the suite is red. §2.3 makes this structurally true rather than
   aspirational.
3. **Exactly one live manifest.** `MANIFEST.json` covers `contract/**` only — without exception,
   without a hand allowlist — and never covers itself or `generated/**`. No second manifest and no
   generated release envelope is created.
4. **No digest outside the manifest.** No generated file contains a digest of itself or of any
   generated file. **The v1 signature-file exception is deleted.** No author-authored file may
   carry any digest, path, count, generation identifier or commit identifier (§1.3).
5. **No hand-maintained cardinality.** Every count is `len(...)` or a set value evaluated at
   render time. Counts are illegal as primary input (§2.1).
6. **Historical generations are Git evidence.** Superseded prose is classified
   `HISTORICAL_NONOPERATIVE` in place (§9): never a manifest member, never authority, never an
   input to any cardinality. No path moves.
7. **Verification compares generated bytes to source.** `verify.py --check` re-renders into memory
   and diffs. It never compares a document to its own testimony about itself.
8. **The trust root is protected.** §2.4.

### §1.3 Acyclic release binding — the Git object graph, no copied digest

Author-authored acceptance material may contain **only** the exact token and the fixed
negative-authority text of §10.5. No path, count, digest, generation or commit identifier appears
in it. The external binding is the Git object graph, whose edges are cryptographic and are not
typed by a human.

| Object | Rule |
|---|---|
| **Candidate `C`** | One M3 commit freezing `contract/**`, `generated/**`, the generator, verifier, provenance gate, schema and template grammar. |
| **Reviews `RX`, `RY`** | Each descends from `C` and adds exactly one file under `reviews/`. No other path differs from `C`. |
| **Closure `L`** | Combines `RX` and `RY` review evidence. Every reviewed surface at `L` is byte-identical to `C`. |
| **Release `T`** | One cryptographically signed **annotated Git tag** targeting `L`. Its message is the exact acceptance token and nothing else. |

`verify.py --check --release-ref <tag>` is **mandatory**; release status is false unless it passes
in full. From the object graph alone it checks: that the tag is annotated and signed and the
signature verifies against the pinned author identity; that the tag message is byte-exactly one
acceptance token with no other content; the DAG shape above, including that reviewed surfaces are
identical across `C` and `L`; the review-only diff property of `RX` and `RY`; ordinary `--check`
mode, the provenance gate (§2.1) and the full suite at the tagged tree; and the derived
open-blocker state (§5.3), which is **reported**, never copied into the tag.

This is a **future** gate. **No Git object is created by this charter**, and §10 authorizes none.

### §1.4 Dependency policy — recommendation

**Recommended: stdlib only.** The repository already supplies `canonical_json` / `sha256_*` /
`atomic_replace` in `src/philosophia/officina/canonical.py`, frozen dataclasses and pytest;
exhaustive enumeration of a finite machine is cheap in pure Python. A schema framework would add
an unreviewed third-party semantic layer to the one part of the system that must be auditable by
reading it, and the provenance gate must be readable independently of any library. Hypothesis is
acceptable as a **dev extra, test-only**, never imported by `contract/**` or `tools/**`, for §5.2
byte-surface property tests only. Under either choice the contract and the trusted base stay
importable with zero non-stdlib dependencies. T-3 carries the decision.

## §2. The provenance trust root

### §2.1 `G-PROV` — the independent provenance gate

`tools/officina_contract/provenance.py` is part of the M3 trusted base and part of the definition
of a green tree. **It must not import or call the renderer**, enforced by an import-graph
assertion and an AST check. Working from raw repository bytes it must:

1. reject symlinks and non-regular files anywhere under `contract/**`;
2. recursively enumerate the exact regular-file set under `contract/**` with **no hand-written
   allowlist**;
3. independently SHA-256 those bytes and require exact equality with the canonical `MANIFEST.json`
   records — rejecting every omission, every extra, and every supplied or expected digest field;
4. enforce a **closed machine-readable contract schema** that labels each field `PRIMARY` or
   `DERIVED` and makes counts, inventories, digests, generation identifiers, replacement claims
   and duplicated authority edges **illegal as primary input**;
5. restrict documentation templates to a declarative placeholder/layout grammar carrying
   presentation labels only — **no factual and no authority sentence** (§2.3);
6. parse the generated factual records back and independently recompute each from the contract IR;
7. reject digest-shaped and generation-shaped literals from every live location except the
   canonical digest field of the one manifest;
8. carry the §2.5 mutation fixtures and prove each fails the gate **even when** ordinary
   render/check byte comparison passes.

### §2.2 `G-TPL`, `G-SRC`, `G-CARD`

Three rules of different kinds, scoped by location. A blocklist over unbounded prose is always
evadable; each of these is an allowlist, a citation requirement or an evaluated-value comparison.

**`G-TPL` — allowlisted template grammar over `tools/officina_contract/**`.** Not a heuristic
blocklist. Every literal reaching an output-writing call or a template body must belong to the
declared grammar: Markdown layout characters and a declared heading vocabulary containing no
digit, no path separator, no number word and no authority verb. Everything with semantic content
must arrive as an interpolated name bound in `contract/**`. The permitted set is finite; the
forbidden set is not enumerated. Excluded literal classes, named for the gate's error messages:
digest-, count-, path-, generation- and authority-verb-shaped.

**`G-SRC` — resolving citation over `contract/**`.** Every module-scope literal must either be a
member of a declared collection or carry a `# PROTOCOL: <path>#<section>` citation resolving to an
existing file and section in the Git-bound tree. **Exactly one** citation per protocol constant:
zero fails and two fail. **A field declared `DERIVED` may not carry a citation of this class** —
the citation is what distinguishes a protocol constant from a derived fact, so a derived fact
claiming one is a gate failure, not a style defect. Cited protocol constants survive; an uncited
`ROUTE_COUNT` has no signed source to cite and dies.

**`G-CARD` — evaluated cardinality, not AST.** Import `contract/**`; for every declared collection
`C`, assert that no module-scope binding holds a value equal to `len(C)` or to any declared set
value. This catches `2 * 4`, `int("8")` and every computed cardinality that AST inspection cannot
see.

### §2.3 Templates emit layout, never sentences

Every normative sentence in `CONTRACT.md` is emitted from a `NORMATIVE_TEXT` mapping in
`contract/constants.py`: a declared `PRIMARY` fact, a manifest member and an M4 review object.
Templates supply placement only. A generated, non-editable header — itself emitted from constants
— states that the document is generated, is documentation and not authority, and that `contract/`
governs on disagreement. A template sentence asserting something the IR does not encode has no
place to live, so §1.2(2) becomes structurally true.

### §2.4 The reviewed trust root

The provenance gate, the contract schema, the template grammar, the renderer and the verifier are
the **trust root**. Any change to any of them invalidates prior green status and requires the full
independent M4 review; it is never an ordinary source fix. This is a stated premise, not an
omitted one: no in-repository theorem can protect against malicious replacement of its own checker
while still calling the result a green tree.

### §2.5 Mutation fixtures — one per malicious-green counterexample

Each must fail `G-PROV` while ordinary render/check byte comparison passes.

| # | Mutation |
|---|---|
| MF-1 | A primary count / inventory / replacement field added to schema-valid source and consumed by the renderer. |
| MF-2 | A hand-typed count, path, generation or authority sentence in the renderer or a template. |
| MF-3 | A hand allowlist that omits one regular file under `contract/**`. |
| MF-4 | A manifest record carrying a supplied or expected digest instead of a recomputed one. |
| MF-5 | An extra regular file under `contract/**` absent from the manifest. |
| MF-6 | A symlink or non-regular file under `contract/**`. |
| MF-7 | A generation-shaped string in source data, a docstring, a template or generated prose. |
| MF-8 | A cardinality bound as `2 * 4`, `int("8")` or an English number word. |
| MF-9 | A protocol-shaped constant with no resolvable citation; and a `DERIVED` field carrying a `PROTOCOL` citation. |
| MF-10 | A template sentence asserting an authority claim the IR does not encode. |

### §2.6 The theorem, stated narrowly

*For every tree passing the **unchanged, independently reviewed** provenance gate, every published
derived claim is independently recomputed from the complete current authoritative file set.*

It does **not** claim: protection against malicious replacement of the checker itself (§2.4);
correctness of the primary author choices, since a wrong primary fact can be green; coverage of
anything outside a green tree; or that the machine is right rather than that the documentation
does not lie about the source.

### §2.7 Equivalence ledger — evidence, never a manifest exception

`successor/officina/migration/EQUIVALENCE_LEDGER.md`, **outside `contract/**`**. M1 writes it
once, mapping each atom (§3) to its primary locator and to the executable test that pins it. It is
reviewed at M4 and is thereafter evidence: not a runtime authority, not a manifest member, never
regenerated, never an input to any cardinality. No archive operation moves it.

## §3. Closed semantic-atom inventory

### §3.1 What an atom is, and why the register replaces I-1..I-15

A **semantic atom** is one operative meaning with **exactly one** primary locator and, from M2
onward, **exactly one** executable test. The v1 thematic list incorporated large unnamed sets by
reference — "the KG-2 machine", "the classifier phases" — so a conforming implementer could omit a
dimension or select a reading while staying inside the wording of an item. That is closed here.
`contract/data/atoms.json` is the **atom register**: live authority, a manifest member, an M4
review object. M1 populates it. Its schema requires per atom an id, its family, its primary
locator (`<path>#<section>` at the Git-bound tree), its closure rule, and — from M2 — its test id.

The register is **closed** in both directions. **Source closure:** the source set is fixed by the
§3.3 table; M1 may not add a source outside it, and adding one is a scope extension under §5.4(3).
**Atom closure:** within each named section the atom set is derived by the stated closure rule
mechanically, not by editorial judgement. `G-ATOM` fails M1 if any atom lacks exactly one locator,
if two atoms share a locator and a meaning, if any locator does not resolve, or if a family's
closure rule yields an atom absent from the register. **No historical prose is copied:** the
register holds locators and closure rules, never quoted clauses.

### §3.2 Blocked decision slots

Where a named section admits more than one reading, M1 records a **blocked decision slot**: an atom
whose value is absent and whose status is `BLOCKED_DECISION`. **M1 and M2 may not choose it, by
preponderance or otherwise.** A blocked slot is raised to the author; it never becomes a default.
The one already-known instance is resolved structurally rather than by choice in §4.3, and this
charter carries no other pre-resolved reading.

## §4. Semantic independence and the KG-2 factorization

### §4.1 One live primary relation; projections are generator tests only

`contract/data/kg2_routes.json` holds a **closed guarded transition table**; `machines.py` holds a
small **fact-free evaluator** over it. This pair is the only object that governs. Route and write
counts are `len(...)` over the table. Because the evaluator contains no facts, coding it twice
checks nothing, and this charter does not pretend otherwise.

The ordered-machine and guard-row projections are both emitted from the one declaration. Their
agreement is a **generator and ordering test** — it catches the ordering defect class the X line
found at v2.15 — and is **not** an independence check. Two projections of one declaration agree by
construction, including when the declaration is wrong; the v1 sentence claiming otherwise is
deleted.

### §4.2 Two independent checks, neither of them live authority

**O1 — standing weak property oracle.** Hand-written in
`tests/test_officina_contract_properties.py`, permanent, test-only. Phrased strictly as
constraints over enumeration *outputs*, never as an alternative route function: at most one write
across any evaluation; no write where the licensing conjunction is false; no observation before
its authority gate; zero signals on any table containing a protected target; role-conditioned NULL
fields. Because every property is **strictly weaker** than the transition relation, O1 duplicates
no governing fact and **cannot become authority** — it may refuse unsafe behaviour, never define a
route. Divergence between O1 and the relation is a finding, not an authority conflict.

**O2 — disposable M4 transcription.** At M4 an independent reviewer codes an evaluator from
`generated/CONTRACT.md` **alone**, never opening `contract/**`, enumerates the full declared
product and diffs the route vector once. The result is recorded in that reviewer's M4 review file.
O2 is **never** committed to `contract/**`, is **never** a manifest member and is **never** re-run
in CI. Its provenance runs outside the declaration, which is the whole of its value.

**Staleness (`G-STALE`).** The M4 review file records the canonical route-vector digest O2 agreed
with; the release check (§1.3) recomputes that digest at the tagged tree and fails on mismatch.
The recorded value is a **pinned expectation whose mismatch is the signal** — it asserts no fact
and confers no authority. It lives in reviewer evidence under `reviews/`, outside `contract/**`
and `generated/**`, so §1.2(4)'s prohibition on digests in **author-authored acceptance material**
is untouched: the acceptance tag stays token-only.

### §4.3 `ObservationOutcome` — resolving 4-vs-6 without an author choice

The declared `KG-1 result × EINTR` pair is not a product: "retried through the deadline"
determines the observation result, so the Cartesian product contains self-contradictory tuples,
and the divergence between the two reported write counts is entirely a disagreement about whether
to count impossible tuples. Both readings agree on every realizable combination. There is
therefore **no semantic dispute and no author choice to expose.**

- The dimension pair is replaced by **one sum type `ObservationOutcome`** whose variants encode
  the feasible states: present-and-valid, absent, unreadable, unparsable, primitive fault, and
  error-after-deadline-exhaustion. Impossible tuples become **unrepresentable**.
- The forcing enumeration clause is **deleted, not interpreted**. M2 adopts no reading and
  exposes no author choice.
- `render.py` publishes the **full sum-type population** and the **feasible route and write
  counts**, every figure `len(...)` at render time. This charter fixes no figure and copies none.

### §4.4 `G-DIM-1..4`

| Gate | Rule |
|---|---|
| **G-DIM-1** single declaration | The frozen input type's field set equals the declared dimension key set. A dimension cannot exist outside the declaration. |
| **G-DIM-2** read-coverage | Enumerate with the input wrapped in a recording proxy: observed reads equal declared dimensions. A dead dimension fails; a read of an undeclared name raises, with no fallback branch. |
| **G-DIM-3** closure | AST assertion that transition functions reference no free name beyond their parameters, `contract.constants` bindings and the stdlib allowlist. No dimension may enter via a module global, the environment, a clock or an import. |
| **G-DIM-4** product faithfulness and completeness | The feasibility predicate over the declared dimensions is identically true — a non-empty infeasible set is a **declaration defect** to be collapsed into a sum type, never patched by a rule. And the declared dimension set equals the A-0 atoms in the register. |

A missing dimension, an illegally independent pair, or a dimension the machine consults but does
not declare fails at M2 or M4. What remains irreducibly human is bounded and finite: *is there a
distinction present in the §3.3 sources and absent from the dimension declaration?* — one diff
against the atom register, performed once at M4.

### §4.5 Derived tripwires

`render.py` emits into `CONTRACT.md` one derived block: per-route counts over the declared
product, per-route counts over the feasible subset, the write count, and the canonical
route-vector digest. Every value is computed at render time. These are **review tripwires, not
primary facts**: any semantic change to the table moves one generated line, `--check` forces the
re-render or the suite is red, and the diff is a one-line signal no reviewer can miss.

## §5. Verification strategy and the crash-cut boundary

### §5.1 Finite machines — exhaustive, never sampled

Enumerate the complete declared product and assert over every combination: exactly one route
applies; never zero; never two or more; the ordered and row-predicate projections agree; the write
count equals the size of the licensing conjunction; no observation and no write precedes its
authority gate. Totality is asserted over the **full declared product** — fail-closed demands that
even an unreachable input route deterministically — while published counts are the feasible ones.
Classifier phases: every fixture under every permutation, asserting exactly one distinct answer
per fixture for terminal, qualifier, per-entry token and recorded site.

### §5.2 Byte surfaces, golden fixtures, absence checks

Property and mutation testing is applied **only** to the parser, canonicalizer and framing code,
whose input domain is unbounded: round-trip `parse(render(x)) == x`; canonicalization idempotence
and byte-stability; every mutation of a valid frame either re-renders identically or is rejected,
never silently accepted as different; and a mutant weakening any closed key set or bound must fail
at least one test. Deterministic by default: pinned seed plus a checked-in corpus of previously
failing inputs. Finite machines are never sampled and byte surfaces are never claimed exhaustive.

`generated/**` is the golden fixture: `--check` regenerates into memory and refuses on any byte
difference. Import and call-surface checks are retained where the invariant is about the
**absence** of a capability: AST assertions that `contract/**` imports nothing outside the stdlib
allowlist, and that modules bound to the contaminated-supervisor role contain no call to A-2's
forbidden primitives. One disposable integration smoke test constructs, renders, verifies and
tears down in a temporary directory, touching no real `T` world, drawing no entropy, spending no
`E1`/`E2`/`E3` and creating no runtime artifact.

### §5.3 Crash-cut — M3 tests `src/**`, edits nothing

`CANON` is classified **dependency under observation**: not a member, not salvage, not extracted
by copy. **M3 may import and test the existing durability primitives; M3 may not edit `src/**`.**

A crash-cut failure attributable to `src/**` is **not** an M3 terminal failure and **not** grounds
to widen M3's edit rights. It produces exactly two things: (1) a **derived, machine-readable M6
blocker record** generated under `successor/officina/migration/blockers/` from the failing test's
own collection output, never hand-typed; and (2) a **strict expected-failure test**
(`xfail(strict=True)`) naming the atom violated and the blocker id.

Strict expected-failure is what makes this fail-closed rather than a waiver: the suite is green
while the defect stands, and the moment the defect is fixed the test fails as an unexpected pass,
forcing the marker's removal. The blocker can be neither silently forgotten nor silently resolved.
M3's gate closes only when every such failure carries both. The accepted inactive contract **may**
retain an open implementation blocker; **M6 cannot close while one exists.** The release check
reports blocker state (§1.3); its count is derived from a collection run and is never copied into
the tag.

### §5.4 M6 discovery — classify exactly once

| Case | Disposition |
|---|---|
| 1. Implementation detail | Stays in `src/**` and its tests. Creates no contract authority. |
| 2. Consequence of an existing atom | A derived test only. No new primary atom. |
| 3. Genuinely new or contradictory invariant | Emit `M6_BLOCKED_NEW_INVARIANT`. The accepted contract is **not** edited. A separate future signed scope-extension route is required. |

Case 3 **cannot** amend this charter, reopen M1/M2, reset any counter, or authorize integration.
This is what stops "charter amendment" from becoming the renamed generation loop the charter
exists to end.

### §5.5 What tests cannot prove

That the extracted atoms are the right ones — bounded by the equivalence ledger, M4 and M5, never
by tests. That the kernel behaves as the pinned semantics assert — declared pinned assumptions with
citations, tested only against a model, re-examined once at activation review. Real concurrency
under real scheduling — bounded by fail-closed defaults and by `T` activation being separately
authorized and out of scope. And the bounded residue of §4.4.

## §8. Episode, round and the non-resettable stop rule

### §8.1 Identities

- **Episode.** One migration episode is keyed by the **first M0 signed Git object**. Its UTC
  start and its 21-day deadline are immutable and are inherited by every rename, split, merge,
  repair or successor package with substantially the same inputs, outputs or authority boundary.
- **Round.** One round is **one byte-distinct candidate followed by any external evaluation**,
  whatever it is called — review, confirmation, audit, closure, pre-review. Simultaneous X and Y
  evaluations of identical candidate bytes are **one** round; changed bytes resubmitted are the
  **next** round. This resolves M4, itself a review package, without special-casing it.
- **Scope.** Counters attach to **artifact scope**, not package name. Split, merged or renamed
  scopes inherit the maximum applicable counter.

### §8.2 This charter's own counters

The v1 X/Y review is **round 1**, and the byte-identical confirmation of these v1.1 bytes is
**round 2**, for the **charter-design** scope. M0 starts the separately named **implementation**
episode with its own counters. Neither counter may be relabelled into the other, and neither is
reset by the transition.

### §8.3 Non-resettable, and the redesign threshold

The two-round limit and the 21-day deadline are **excluded from every override**. M0 cannot be
re-signed to reset them. No author act extends this episode once either triggers.

On either trigger, work **stops** and exactly one of three terminal destinations is selected: (a)
accept a reduced contract covering only the converged atoms; (b) return to scientific development
with the P1 cell explicitly unresolved and the harness inactive; (c) a new signed route decision.
A later route is a **new** route; it cannot retroactively make this episode green. Every other
limit in this charter may be exceeded only by a new author-signed route decision naming the limit,
the new value and the reason. Silent expansion is prohibited.

## §9. Disposition — logical archive only, no path moves

**No physical move.** M0 creates one primary `STATUS_POLICY.json` under
