## 4. Total stat / signal / waitpid state machine

```text
STAT_OBSERVE(pid) → ABSENT | PRESENT_VALID | UNREADABLE | UNPARSABLE | ERROR
  ENOENT/ESRCH ⇒ ABSENT | EACCES/EPERM ⇒ UNREADABLE | EINTR ⇒ bounded retry
  then ERROR | other OSError ⇒ ERROR | parse failure ⇒ UNPARSABLE
  Only ABSENT and PRESENT_VALID may contribute to identity or death.
  UNREADABLE/UNPARSABLE/ERROR ⇒ no kill, no unlink, no death conclusion.

SIGNAL_ATTEMPT(pid, sig) → SENT | GONE | INTERRUPTED | DENIED | ERROR
  success ⇒ SENT | ESRCH ⇒ GONE (never death alone; proceed to WAIT_PROVE)
  EINTR ⇒ retry the same signal within the existing deadline, then ERROR
  EPERM ⇒ DENIED, other ⇒ ERROR — both: no further signal, no unlink
  Schedule: SIGTERM at t0; poll to t0+D/2; SIGKILL; poll to t0+D; edges at ≥.

WAIT_PROVE(pid_mid) → PROVED_DEAD | NOT_YET | INCONCLUSIVE
  (pid_mid, status) ⇒ PROVED_DEAD | (0,0) ⇒ NOT_YET | ECHILD ⇒ PROVED_DEAD
  EINTR ⇒ bounded retry then INCONCLUSIVE | other ⇒ INCONCLUSIVE
```

**Why exactly two outcomes prove death.** `waitpid` returning `pid_mid` is the
strongest proof: the CLI is the parent by construction, the child terminated,
and the kernel reaped it in that call. `ECHILD` for a pid this CLI forked can
only mean it was already terminated **and reaped**, and since the contract
installs **no signal disposition** anywhere (`signal` is outside the allowlist),
`SIGCHLD` keeps its default, no child is auto-reaped, and this route is the only
reaper. **The proof is `/proc`-independent.** **PID reuse:** an unreaped
terminated child is a zombie whose pid cannot be reassigned, so every signal and
stat before `PROVED_DEAD` targets this child or nothing; after `PROVED_DEAD` the
route never touches the pid again. **Ordinary-exit races:** exit before any
signal, between the signals, or between polls all converge on `PROVED_DEAD`.

## 5. `SPAWNING`-only recovery automaton and the death-before-unlink proof

**The boundary, stated precisely.** Death-before-unlink protects a record that
is the **sole durable handle on a process that may still act**:
`SPAWNING_CHILD` (grandchild), `SPAWNING_GROUP` (session/group),
`SPAWNING_MIDDLE` (middle child). **`SPAWNING.json` names only the CLI** — it
is never a handle on any of those processes — so removing it can orphan nothing
and disrupt no continuing action. The abandoning CLI therefore always removes
its own `SPAWNING.json` while holding the lock; the other three are never
removed without a proof.

**Two-supervisor safety.** Removing `SPAWNING.json` while a middle child may
live cannot produce a second supervisor: `m5` (the stage-2 gate) is released
only by the CLI's `c12` write on `rel2_w`, and the abandoning CLI has closed
`rel2_w` through `CLOSE_OWNED`; since the middle closed its own copy at `m1`,
the CLI is the sole remaining writer, so `m5` observes **EOF** — or its bound
expires — and it exits without ever forking a grandchild or installing an
identity.

| Terminal | Condition | Actions | Surviving state | Forward route |
|---|---|---|---|---|
| **T1** | `PROVED_DEAD` | `CLOSE_OWNED` cleanup; ordered removal of all four records (§U6.3, fsyncs, ENOENT-tolerant, matched by `spawning_id`); lock close; refusal (retryable) | none | next attempt at P0 |
| **T2** | not proved dead, a `PRESENT_VALID` stat was obtained | install `SPAWNING_MIDDLE.json` with the signed §U2.2 `c7` key set (every field known; nothing fabricated); remove **only** `SPAWNING.json`; lock close; refusal (retryable) | `SPAWNING_MIDDLE.json` | P2b refuses while live; once aged past `T_SPAWN_BOOTSTRAP_MAX_AGE_NS` the **existing** `s4` tier kills by pid + start identity, proves death, and `c1b`'s P3 removes it |
| **T3** | not proved dead, no `PRESENT_VALID` stat ever | install nothing; remove **only** `SPAWNING.json`; lock close; refusal (non-retryable, named terminal) | at `c5`/`c6`: none; at `c7`-after-rename: `SPAWNING_MIDDLE.json` | P0, or the T2 route |

| Scenario | Continuation |
|---|---|
| **long-lived CLI**, `c5`/`c6` failure, child proved dead | T1; no record survives; **no wedge** |
| **long-lived CLI**, child not proved dead, identity known | T2; `s4` resolves it; **no wedge** |
| **long-lived CLI**, identity never obtainable | T3; nothing survives at `c5`/`c6`; **no wedge** |
| **stopped middle child** | `SIGKILL` cannot be blocked or ignored and terminates a stopped process ⇒ `PROVED_DEAD` ⇒ T1 |
| middle exits before / between signals | `GONE` ⇒ `WAIT_PROVE` ⇒ `PROVED_DEAD` ⇒ T1 |
| unreadable / unparsable `/proc` | not identity-safe ⇒ no kill; `WAIT_PROVE` is `/proc`-independent and usually still proves death ⇒ T1; else T3 |
| `ESRCH` / `EPERM` / `EINTR` | `GONE` ⇒ proof; `DENIED` ⇒ T2/T3; `INTERRUPTED` ⇒ bounded retry |
| `waitpid` `0` / `pid` / `ECHILD` / error | `NOT_YET` / `PROVED_DEAD` / `PROVED_DEAD` / `INCONCLUSIVE` |
| PID-reuse attempt | pre-reap the pid cannot be reused; a captured-identity mismatch ⇒ no kill ⇒ T2/T3; post-`PROVED_DEAD` the pid is never touched |
| restart before / after the middle's own bound | crash releases the CLI's fds and lock reference; records survive; next P0–P3 governs; after the bound P3 proves death by absence |
| crash after the T2 install, before the `SPAWNING.json` unlink | both records exist; the next preflight applies P1/P2/P3 in child→group→middle→spawning order; the crashed CLI's record is P3-removable by proved absence |
| crash between any unlink and its `fsync`, or after the lock close | ENOENT-tolerant ordered resumption; a second invocation starts clean |

**Named residual:** a **deliberately `SIGSTOP`ed** middle child holds its
fork-shared lock reference until killed. In T2 it is tracked and `s4` reaches
it within a bounded time; in T3 it is untracked and the singleton stays held
until that process is terminated — the signed A3 procedural residual, the same
class already named in §U2.7 and §V216.3, permanently non-citable and **not**
claimed impossible. This is strictly narrower than v2.1.6, where the same case
**plus every ordinary long-lived-CLI case** wedged.
