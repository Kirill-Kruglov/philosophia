## 4. Descriptor ownership and idempotent cleanup

`BOOTSTRAP_FD_CLEANUP(owned)` iterates the fixed order
`[boot_r, boot_w, rel1_r, rel1_w, rel2_r, rel2_w, rel3_r, rel3_w]`, skips
un-owned entries, and for each owned entry: `EBADF` ⇒ success; `EINTR` ⇒
**closed, never retried** (Linux releases the descriptor even on `EINTR`, and a
retry could close a descriptor since opened at the same number); any other
errno ⇒ **closed**. It never raises, empties `owned`, and is idempotent. It
never touches a filesystem object, takes no lock, kills nothing, and never
closes the `SPAWN.lock` descriptor.

| End | Owned from | Owners after `c5` | Normal close | Failure-path closer |
|---|---|---|---|---|
| `boot_r` | `pipe2` #1 | CLI | CLI after `c13` | CLI cleanup |
| `boot_w` | `pipe2` #1 | middle; grandchild copy at `m7` | CLI `c5`; middle `m8`; grandchild `g1` | each owner's cleanup |
| `rel1_r` | `pipe2` #2 | middle | CLI `c5`; middle `m1` | each owner's cleanup |
| `rel1_w` | `pipe2` #2 | CLI **and** middle until `m1` | CLI `c8`; middle `m1` | each owner's cleanup |
| `rel2_r` | `pipe2` #3 | middle | CLI `c5`; middle `m6` | each owner's cleanup |
| `rel2_w` | `pipe2` #3 | CLI | CLI `c12` | CLI cleanup |
| `rel3_r` | `pipe2` #4 | middle (for inheritance), then grandchild | CLI `c5`; grandchild `g1` | middle cleanup (this is what gives `c13` EOF at `m7` failure); grandchild cleanup |
| `rel3_w` | `pipe2` #4 | **CLI only** after `m1` | CLI `c16`; middle `m1` | CLI cleanup |

At every instant each end is exactly one of: not yet created, owned by the
listed processes, or closed. Together the normal close points and the failure
closers cover every end in every phase, so **no descriptor leak is reachable**,
and no uncaught exception, process exit, finalizer, or implementer convention
owns a transition.

`REFUSAL_SEQUENCE`, invoked by every CLI abandonment path (`c1a` expiry, `c1b`
refusals, every `c3` cut, `c4`, every stage-1/stage-2 helper route at
`c8`/`c9`/`c12`/`c13`/`c16`, `c17` expiry): **1.** kill and prove death if the
stage requires it — identity-validated first, never on a start-identity
mismatch — *before* the record removal, because the kill reads those records;
**2.** `BOOTSTRAP_FD_CLEANUP`; **3.** §U6.3 ordered removal
`SPAWNING_CHILD → SPAWNING_GROUP → SPAWNING_MIDDLE → SPAWNING`, each unlink
followed by a `T_SUPERVISOR/` `fsync`, `ENOENT` tolerated, **while still
holding `SPAWN.lock`**; **4.** release the lock; **5.** return the refusal with
its pinned `retryable`.

|---|---|---|---|
| `pipe2` #1 fails | ∅ | full sequence | true |
| `pipe2` #2 fails | 2 ends | closes exactly those 2 | true |
