## 4. Complete custody-location table and the before/after-rename proof

| # | Location | Role |
|---|---|---|
| L1 | `runtime_control/T_SUPERVISOR/operations/<op>/out/` | source custody; also the quarantine custody location (§N2.1 defines it) |
| L2 | `runtime_control/T_SUPERVISOR/operations/<op>/` | may hold **only** `{BOUND, OPERATION, RUNNING, SETTLEMENT, QUARANTINE, DELIVERY_ACK}.json`; any other entry is unknown custody |
| L3 | `runtime/T_PROMOTED/<op>/` | promoted custody |
| L4 | `.<name>.tmp` durability temporaries under L2 or beside L3 | partial writes that can hold bytes |
| L5 | any other entry under either fixed root whose name contains `operation_id` | additional/unknown custody |

The set is derived from the immutable `operation_id` and two fixed roots; no
record field is trusted. `out/` is the only protocol-allowed staging or
pre-rename location, because promotion is a single same-device
`os.replace` guaranteed by the §Z9.4 `st_dev` serve preflight.

| Crash direction | Real custody | v2.1.1 | v2.1.2 |
|---|---|---|---|
| **before** the promotion rename | L1 present, L3 absent | a `custody_root` naming the destination passed conjunct 10 and **released capacity while bytes existed** | P2/P3 find the operation directory holding `out` ⇒ **REFUSE** |
| **after** the promotion rename | L1 absent, L3 present | a `custody_root` naming the source passed and **released while bytes existed** | P4 finds `T_PROMOTED/<op>/` ⇒ **REFUSE** |
| quarantined (custody never moved) | L1 present | a destination-named proof could pass | P2/P3 ⇒ **REFUSE** |
| stray temporary or `<op>`-named entry | L4/L5 present | undetected | P5/P6 ⇒ **REFUSE** |
| unreadable level | unknown | — | P7 ⇒ **REFUSE**; never assume absence |
| all locations proved absent, only immutable records remain | none | — | release exactly `bytes_reserved`, once, recording `custody_locations_proved` |

A pre-rename settled record can therefore never prove post-rename absence:
the settled record is not consulted for the proof at all. Interactions pinned
in §N2.6: quarantine retains the reservation until the author removes L1;
partial promotion cannot exist; crash reconstruction still counts
record-less custody at the full ceiling and never re-measures downward;
delivery acknowledgement releases nothing; the disposed record is installed
only after the whole set is proved absent in the same epoch.

```text

      c2 SPAWNING.json (no-replace, §3 durability)

      c10 write b"\x01"; close release-W   m6 _exit(0)          instruction
      c11 bounded identity poll                              g1 scrub fds
      c12 release SPAWN.lock                                 g2 endpoints,
                                                                watchdog,
                                                                bounded ack
                                                             g3 IDENTITY,
                                                                unlink markers,
                                                                close lock fd
```

| Path | Content-byte writes | Content-byte hashes |
|---|---|---|
| framed transport write pass (§N4.1) | **1** per byte | **0** — no hash object is instantiated; only `bytes_written[rel]`, `bytes_written_total`, `frame_count` |
| pre-settlement verification pass (§N4.2) | 0 | **1** per byte, through an inode-verified freshly re-resolved descriptor |

Ceilings without hashing: the header check enforces path grammar, depth, file
count ≤ `16 × device_units`, `type(content_bytes) is int > 0`, and
`bytes_written_total + content_bytes ≤ bytes_reserved` **before** anything is
created; a chunk that would cross the reservation writes nothing further,
closes the read end, kills the group, proves death, and quarantines
`BOUND_EXCEEDED`. The worker's `frame_count`/`total_content_bytes` are checked
against the supervisor's own counters and can only cause a fail-closed
`TRANSPORT` quarantine.

`SETTLEMENT.json` ⇒ `SUPERVISOR_CRASH` quarantine at the conservative

retained in full: `(st_dev, st_ino)` against the descriptor held since before
the first byte plus `st_nlink == 1` and exact size (inode substitution), and
the whole-file re-read (equal-size content substitution). The pass and the
settle step share one lock epoch, and §N4.4 clarifies that a control step
serviced between chunks may only read and buffer — never apply an effect —
because a lock epoch is not reentrant. The `out/`-directory-swap-by-name
residual is preserved verbatim as A3 procedural; nothing more is claimed.
