## 4. The `CLOSE_OWNED` state machine, applied by name everywhere

```text
CLOSE_OWNED(owner, fd, context) → {CLOSED, CLOSED_ABSENT, CLOSED_ERROR, NOT_OWNED}
 0. fd ∉ owned(owner)   ⇒ NO syscall; return NOT_OWNED; continue
 1. os.close(fd)
 2. success ⇒ CLOSED | EBADF ⇒ CLOSED_ABSENT | EINTR ⇒ CLOSED_ERROR |
    any other errno ⇒ CLOSED_ERROR
 3. owned(owner) := owned(owner) \ {fd}      — unconditional, exactly once,
                                                BEFORE any routing
 4. the NUMBER is never used again: never retried, re-closed, forwarded, or
    compared (the kernel may have reassigned it)
 5. routing: CLOSED / CLOSED_ABSENT / NOT_OWNED ⇒ continue;
             CLOSED_ERROR ⇒ the context's pinned continuation
```

`EINTR` and other errors remove ownership because on the pinned Linux target
the descriptor is **released before the error is reported**; retrying could
close an unrelated description at a reused number. `EBADF` is fail-safe:
nothing was closed. Diagnostics, if recorded, are closed control-plane facts
(one of four labels plus an errno) that may never enter selection, Q/C,
C1–C6, custody, capacity, an author decision, an invalidity cause, or any
scientific or resource interpretation, and may never alter routing.

**Applied by name at every site.** Uniform `CLOSED_ERROR` continuation =
`CONTINUE`, justified once: the descriptor is released in every outcome except
`EBADF` (nothing open) and `NOT_OWNED` (nothing attempted), so the observable
pipe state — reader/writer counts and therefore every EOF and `EPIPE`
consequence — is identical to success. No site's correctness depends on a
close's *return value*, only on the release, which is unconditional.

`rel1_r`; the writers are the CLI's `rel1_w` **and the middle's own inherited

attempt's** records by `spawning_id` in §U6.3 order with per-unlink `fsync`,
